# ТВ-приложение: телевизор — хаб, сцена в WebView, у телефона нет своего приложения

Нужен аквариум на Android TV без интернета, куда рыбок присылают с телефона.
Решили: ТВ-приложение показывает ту же сцену three.js в WebView и само раздаёт
страницы и API встроенным сервером на Kotlin (NanoHTTPD) в том же формате ручек,
что `server.js`. Телефон открывает этот аквариум в браузере по QR с экрана ТВ —
съёмка уже работает через `<input type="file" capture>`, которому не нужен HTTPS.
С сайтом ТВ не синхронизируется; аквариум на ТВ один, без кодов, паролей и пинов.

## Considered Options

- **Нативная отрисовка на ТВ** (OpenGL ES / Filament / libGDX): быстрее, но это
  переписка сцены, плавания, каустики и скелетной анимации и дальше два исходника.
  Отложено: возвращаемся, только если в WebView даже на низшем качестве нет 30 fps.
- **Нативное приложение на телефоне**: дало бы автопоиск ТВ без QR, но браузер
  уже умеет всё нужное. Добавим обёрткой, если путь через браузер начнёт мешать.
- **nodejs-mobile с `server.js` как есть**: +30–50 МБ и вся интернетная защита
  (пароли, пины, лимиты, SEO), которой в домашней сети нечего охранять.
- **Синхронизация с сайтом**: конфликты, авторизация, коды аквариумов — половина
  `server.js` ради сценария, которого пока никто не просил.

## Consequences

- Пак моделей вшивается в APK при сборке из локальной папки. Лицензия пака
  запрещает перезаливку, поэтому APK только для личной установки, не для магазина.
- Любой в домашней Wi-Fi может добавить или удалить рыбку; удалённое уходит
  в корзину, вернуть — через adb.
- Оптимизация под слабые ТВ живёт в общей сцене и действует и на сайте.
- APK подписывается постоянным ключом с первой сборки: смена ключа означала бы
  переустановку с потерей рисунков на ТВ.
